## Proposed practical route and its real trust cost

Develop an explicit, small, default-off native MIR operational interpreter and
integrated affine-resource checker as a NEW, separately reviewed compiler-TCB
component. Treat its mapping of the supported native execution/heap/pointer
steps to canonical Verus pointer/resource semantics as trusted compiler
interpretation, rather than claim a machine-checked refinement to an already
pinned external native Rust operational model that this campaign has not supplied.

This would enlarge the trusted compiler boundary. Independent source review,
typechecking, tests and mutation rejection would not be relabeled a formal
native-runtime simulation theorem. Proofs using the component would explicitly
depend on the correctness of this new interpretation/checker. A wrong pointer,
event or ownership translation could make those proofs unsound. This is not
merely permission to write compiler code, which139 already supplies; the requested
change is the basis on which a future reviewed implementation may be trusted.

The exact permitted development/adoption envelope would be:

1. A typed, source-bound partial MIR state/step interpreter with an explicit
   monomorphized activation stack, actual outcomes and incoming resource frontier.
   Unsupported instructions, cleanup, loops, alias effects or outcomes refuse;
   no supplied native application summaries or compiler Assume gifts.
2. An explicit interpretation of the SAME selected native returned pointer,
   including provenance/generation and metadata, into the canonical full pointer.
   No address-only equality, independent pointer, static ID/counter witness or
   second wrapper allocation may substitute for that interpretation.
3. Once-only instantiation of already conditionally adopted schema159 for the
   same checked normal-success event, genuine loaded raw/Dealloc types and
   actual typed size/Alignment/layout/runtime/allocator/deallocator conditions.
   Schema159 is not expanded, and null/error/unwind/abort/divergence stay distinct.
4. An integrated affine-flow checker connecting initialized native shadow
   resources through moves, overwrites, borrows, calls, returns, joins and cleanup.
   Local bookkeeping or a non-Clone host node is not sufficient. A limited
   empty-frontier subset must prove its incoming frontier condition from the
   interpreted caller flow, not assume it from an empty local map.
5. No blanket owned-memory/ambient/callback frame is included. Preserving prior
   resources, contents or loans requires explicit checked effects; otherwise the
   subset refuses. Any separately trusted frame relation needs its own exact
   review/disposition rather than this request being read as permission for it.

Before ANY operative use, require a NEW independent review of exact code, exact
semantic rules and actual original-event bindings; an explicit parent disposition
with source/semantic hashes; positive/negative original compiler-only checks; and
an explicit trust ledger. General approval of this envelope would NOT self-adopt
unknown code or unblock an issuer. Network/Git writes, original application/test
execution, source integration, destructive cleanup and weakened admission remain

The checked alternative remains possible in principle: define/select an explicit
