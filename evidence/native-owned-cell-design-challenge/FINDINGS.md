# Independent design findings at frozen 0dd6130f

Verdict: **conditionally feasible for the closed owned/exclusive slice; no admitted-language soundness counterexample found.** The positive type grammar, direct checked-call rule, source spec restrictions and full-unit rejection requirements jointly exclude the shared-framing witnesses. A type whitelist by itself does not implement those requirements. Two concrete implementation/acceptance details need resolution below. Neither is a demonstration that the proposed owned semantics is unsound, and no future implementation is accepted here.

## F1 — Specify the spec-scaffolding boundary before implementing the complete typed-unit gate

**Priority: acceptance blocking, bounded fix.** IMPLEMENTATION_TARGET.md:7–21 requires inspection of all typed bodies and rejects closures, generic/function values, shared executable references and calls other than three methods/acyclic local functions, while permitting scalar specifications. Taken literally over raw typed Rust nodes, that grammar rejects the unchanged positive input itself.

The smallest example is already `owned_goals.rs::exclusive_borrow`, with `ensures result == next`. `source/builtin_macros/src/syntax.rs:1144–1186` builds an `ensures` closure and an array, including a type-only recursive call to the current function under `constrain_type`. Schematically, before normal frontend header extraction:

```text
ensures(|result| [constrain_type(result, exclusive_borrow(cell, next)), scalar_postcondition])
```

This is a source-code-derived schematic, not a measured expanded-HIR dump. The generated closure/function types and bool array are outside V/S; the apparent self call violates a naive acyclic-call scan, and its arguments mention `cell`. Blanket rejection loses the mandatory positive. Blanket omission of closure/spec subtrees loses the spec/capture gate.

Existing lowering already distinguishes this exact infrastructure: `fn_call_to_vir.rs::check_is_builtin_constrain_typ` resolves the actual builtin identity and records `MiscEraseAbsolutely`; `extract_ensures` removes that type-only node, extracts the actual predicates, and records `BodyErasure { erase_body: true, ret_spec: true }` for the header closure. `verus_items.rs` registers the builtin by its diagnostic identity. A spelling, macro span, source attribute or arbitrary `in_ghost` bit is not an adequate exemption.

**Required decision:** define separate executable admission and canonical header/spec admission. Recognize the actual builtin header/scaffolding identity and shape; validate its real scalar/tuple predicates and captures after extracting the type-only machinery. Keep executable closures/function values and user C-bearing spec expressions rejected. The original cell operations inside executable bodies must still be scanned with all adjustments. Do not use already-pruned VIR as the whole-unit inventory.

**Minimum regression pair:** unchanged three goals reach ordinary/Infer full queries; adding a real executable capture of C or a user spec term/quantifier holding C is refused. Exercise a user-authored macro too, so a macro-origin exemption cannot bypass admission. Explicitly test the type-only self call separately from a real recursive executable call. This needs a small canonicalization policy, not general callback effect inference.

## F2 — Native-method authority alone does not provide the mandatory private client final-state query

**Priority: acceptance blocking, bounded fix.** IMPLEMENTATION_TARGET.md:21 and :37 grant private field authority to checked native-method identities/operations; :61 and ACCEPTANCE.md:12 require a body-identical diagnostic on the *local client* `exclusive_borrow`, proving `final(cell).value == next`. That client has a different DefId and its public source postcondition mentions only the returned scalar. Source access to the field is intentionally forbidden.

The design expressly permits test/compiler-generated private postconditions, so this is an unspecified mechanism, not a logical contradiction. It must become an explicit distinct authority or checked end-of-body obligation. The existing descriptor grants encoding visibility, not such a client-query capability. `well_formed.rs::check_datatype_access`, `check_one_expr` and `check_one_place` use function ownership/visibility; `internal_repr::validate_datatype` only revalidates the datatype. Moving a diagnostic into core's module, setting `owning_module=None`, skipping WF, adding a public selector, or supplying the desired equation as a premise would not discharge this requirement.

**Required decision:** pin an internal diagnostic obligation to the exact admitted client body, original mutable input parameter/place and compiler-selected native field. It may inspect that input's final state only for this local checked obligation; it must not grant source field access or a public/importable live-value function. Recheck identity/scope after full Function construction and at the backend boundary. No new state law is needed: the equation is a goal of the ordinary full-body query, using the checked get_mut contracts and ordinary writeback.

**Minimum regression set:** arbitrary initialized entry C with no constructor-value/equality premise; positive final input=next; false final input=old entry value for differing next; remove only the native store/writeback while retaining result=next; corrupt the input place or field/region independently. Run both the solver failure and the correspondence-refusal fixtures. The diagnostic must go through the same checked body pipeline, not an unrelated hand-built SST theorem. The source call bodies and the retained native field store remain unchanged.

The native return-only control in `native_witness.rs` concretely returns 7 while leaving the actual input 3. It demonstrates why the returned scalar alone cannot satisfy this acceptance gate; it is not an admitted verifier counterexample or a state proof.

## F3 — Existing registration and descriptor hooks are insufficient enforcement boundaries

**Priority: required implementation audit, already substantially recognized by the design.** These are concrete hazards, not additional soundness failures in an unimplemented design:

* `checked_foreign.rs::register` is Infer-only, scans `FunctionOrConstInfo::Function` bodies, and skips `external_body`. Its HIR visitor does not establish whole-unit closure. Reusing it as the admission pass omits native/unverified bodies and their nested content.
* `rust_to_vir.rs::crate_to_vir` translates Verus-aware items; external items are mostly recorded as diagnostic names, not checked bodies. `external.rs` classifies native/external/nested items; it is not a positive typed-effect validator. Start from an independently complete local rustc item/body inventory, including nested owners/promotions/adjustments, and reject unknowns before descriptor installation. The checked slice may reject irrelevant unsupported local items as the design specifies.
* `InternalRepresentation` currently describes only Rev and is inactive. Its validation hooks at WF/backend validate datatype shape, not the types/effects in every function or source/diagnostic capabilities. A cell variant needs its own actual use checks. The Rev field-reborrow test demonstrates mechanical current/writeback relations and omission sensitivity only.
* `DatatypeTransparency::Internal` is `#[serde(skip)]`; existing JSON rejection tests and the pre-query pre-crate export gate are useful local-only scaffolding. Retain complete-unit detection even when helper/proof pruning leaves nothing, reject affected exports, and refuse imported generic/abstract cell operations before facts are used. Ordinary `.vir` import trusts baseline artifacts; it does not automatically rescan a native wrapper's implementation. Nonserializability of one descriptor does not itself police every scalar dependent fact.
* Early invalidation in `VerifierCallbacksEraseMacro::config` and `invalidate_export` currently clears selected direct/Cargo outputs, including ordinary artifacts (the local-inference parameter is unused). Preserve it. I found no missing stale-output invalidation rule in this frozen scaffold; test early failure and zero-helper paths rather than assuming a late descriptor check suffices.
* `fn_call_to_vir.rs` substitutes checked VIR call targets; `erase.rs::resolved_call_to_call_erase` controls erasure/keeping of the original typed call. It is not a runtime redirect to the VIR helper. A new cell path must retain original native types/method operands and its original borrow regions in the erased program. Verify the emitted native artifact, not the helper's pretty name.

## Soundness boundary and boundedness assessment

For a lawful owned C, the present scalar content is a value snapshot. An owned move transports that value and consumes the old owner. For a lawful `&mut C`, the native uniqueness rule includes C's contents despite UnsafeCell's shared-reference exception; the actual get_mut is an exclusive field reborrow. Ordinary current/future/writeback rules can describe that state. No identity/address theorem or new permission axiom is needed in this domain. Arbitrary valid initialized u64 input is sufficient, even after earlier lawful shared mutation that ended before the exclusive borrow; no constructor-history premise is justified.

The native !Sync declaration must remain native. It does not prevent legal single-threaded shared mutation and therefore cannot replace the rejection of `&C`/shared outer types or callbacks. Historical scalar snapshots may persist as historical facts. A persistent selector from shared object identity to immutable current contents may not. Hidden aliases, enclosing ADTs, associated projections, generic callbacks, captures, foreign summaries and spec C values are all covered only if the complete grammar and direct-call/spec rules are actually enforced, with unknowns rejected.

`needs_drop(C<u64>)=false` alone does not prove all effects are absent. The full admitted local/body inventory must still exclude destructor-bearing enclosures, foreign/indirect operations, inline assembly, unknown intrinsics and cleanup/unwind/coroutine effects. The existing frontend already refuses inline assembly; keep that refusal. Neither a Drop-free argument list nor a hash is an effect proof. Do not change panic strategy to make rejected cleanup disappear. Inspect the actual original typed method bodies, all blocks and locals, with pre-erasure lifetime/signature validation and independently checked emitted Function/places/read modes.

I found no smaller legal shared-framing witness that also satisfies *all* the design's positive type, call, spec, body and effect conditions. `native_witness.rs` executes direct and outer-shared counterexamples to weakening them; both intentionally violate the proposed grammar. This conclusion is a scoped design feasibility assessment, not a formal ownership theorem, implemented gate audit or verified all-u64 result.

A finite new module for admission/identity/three MIR instances, ordinary body-backed lowering, two narrow compiler authority roles, and existing verifier integration is a plausible bounded experiment. If those three operations require general alias/effect inference, arbitrary native summaries or raw-memory laws, stop at that obstruction. Successful owned support would still prove no shared Mutex invariant, guard acquisition, raw access, release/drop/unwind behavior, atomic constructor, REDB write coupling or crash theorem.
