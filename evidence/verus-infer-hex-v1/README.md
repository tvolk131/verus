# Hex-conservative native byte-pair acceptance

The finite milestone is complete: the actual `Char::decode_nibble`, its original
function-local static initializer, and `hex_chars_to_byte` verify forward decoding
for every pair of bytes. The independent requirement uses ASCII numeric ranges
and the arithmetic equation `16 * high + low`, including mixed case, non-ASCII
rejection, exact offending-byte payloads and high-byte error priority.

Engine implementation: `c8c384a70b23e842ed2edcb2dddc27a3a61dbf61`.
Native implementation: `5ccfbad247d5a332408929173e4072fbf06d8bd1`.
Native baseline: `129db6ac54d25b08e0b927c225aefe4a8df05a57`, version 1.3.0.
The [frozen charter](charter.md) defines the endpoint and its extension boundary.

The table and nibble equations are authored **required behavior**, proved against
their unchanged native bodies. They are not inferred or assumed contracts.
The pair implementation contract is generated by general inference and passes
ordinary soundness, safe-domain maximality and output exactness. An ordinary
application goal then checks the independent arithmetic/error policy. General
goal assistance proves a universal conditional packing lemma using the existing
bit-vector checker before using the identical theorem in that ordinary proof.
No first-party equation, lookup entry or application result is trusted.

The named executable bodies are the existing derived `Char::clone`, the nibble
decoder, pair decoder and ordinary pair goal. The native report lists the table's
unerased proxy too; constants/statics are not included in its named-function
count. The eight verified results include precision and auxiliary obligations;
they are not eight separate production functions. SST packing auxiliaries do
not currently get separate `goal_assistance` rows in JSON; the controlled replay
and ordinary checked auxiliary query establish their use here.

The mutations change a table assignment, swap high/low output, accept an invalid
sentinel, corrupt a low-byte error payload, return a wrong output, and reverse
error priority. These are deliberate test mutations, not upstream defects.
Development evidence also retains rejected frontend/inference probes and an
earlier controller that mishandled the JSON of early filter rejection. Only
`accepted-final` is the acceptance series; it ends with fresh restored proofs
and native tests, with identical source hashes before/after.

## Scope and trust

This certifies the internal two-byte endpoint, not public string decoding.
`ChunksExact`, iterator state and byte locations, saturating position arithmetic,
error conversions and the native unsafe pointer-writing drains remain outside
the proof. Public API boundary tests are tests, not endpoint theorems. UTF-8
lengths/locations are byte-based. A future fixed-array theorem must account for
the native `2 * N` overflow domain. See [the charter](charter.md) and
[native adoption instructions](../../source/tools/check_hex_adoption.py).

The underlying Rust compiler, Verus/vstd models, solver and proof pipeline remain
the trust boundary. New `ok_or` composition uses the existing vstd specification;
no new assumed specification, external body, exclusion, proof block, invariant
or authored trigger was added to the native inputs. Scalar query interfaces are
checked ordinary contracts, not exact-inference certificates for their authors.
The new engine profiles are bounded; this result does not certify arbitrary
Rust, arbitrary table initializers, unsafe decoding, or the whole crate.

Aleph evidence trees are unchanged. All 80 source hashes recorded by the accepted
v4 closure still match its clean fixture, and all nine pinned v3 engine/solver
artifacts match. [Preservation receipt](preservation.json) records these checks.
This acceptance was performed by the implementing agent; no independent-agent
review is claimed. Both repositories were committed locally; nothing was pushed.

## Reproduction and artifacts

Build the implementation commit with Rust 1.99.1 and matching macros/vstd, then
run the controller against the native implementation checkout:

```sh
python3 source/tools/check_hex_adoption.py \
  --native-root /path/to/hex-conservative \
  --output /private/tmp/hex-acceptance-new
```

The output directory must be new. The controller temporarily mutates only the
two native files and restores them in `finally` blocks. Verification invokes
Verus directly on the actual native `src/lib.rs` with `std` and `alloc` enabled;
there is no extracted decoder or substitute proof crate. Native Cargo tests use
the ignored `Cargo.lock`, initially copied from upstream's `Cargo-recent.lock`.
The only tracked manifest change registers the verification cfg for linting.
Offline replay requires the recorded optional dependencies to be cached.
