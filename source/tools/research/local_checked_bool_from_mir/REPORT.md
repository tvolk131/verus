## Actual ordinary path

`checked_foreign.rs` resolves only a direct HIR definition call, in its actual
caller TypingEnv. It identifies the diagnostic From trait in the crate identified
by a core lang item; checks associated method/impl relationship, actual bool
input/u64 Self/output, safe Rust ABI, Item instance and empty final substitutions;
and instantiates the actual typed optimized MIR. No numeric DefId, impl spelling
or debug-text parser selects the instance. Locals, blocks, operations, terminator,
non-dropping types, phase and non-coroutine/constant/coverage/error properties
are checked. Source/debug/local annotation metadata does not add executable
operations. Any unsupported executable operation or extra block/local rejects.

The body is precisely `_0 = Copy(_1) as u64 (IntToInt); Return`, with bool `_1`
and u64 `_0`. Its full ordinary Function uses the existing Copy(bool) read and
bool-cast If encoding. Fresh internal spans, parameter/result binders and read
IDs are separate from HIR nodes. Independent original-MIR/full-Function checking
compares types, modes, local-to-binder mapping, copy, branches, return and absence
of additional effects, separately from the proposed postcondition.

`FunctionOrConstInfo::BodyBackedForeign` is distinct from ForeignFunctionInfo and
external-body stubs. The full helper/stub is registered before function stub
collection and Query maps. Query runs its normal trait demotion, WF, autospec,
mode/resolution and ordinary body/solver pipeline. The full-domain ordinary
proposal has no requires and ensures `r == if b {1u64} else {0u64}`. It is not an
inference summary and has no inferred soundness/maximality/exactness claim.

The direct-call adapter executes inherited trait resolution, argument and impl
path processing, and records the original runtime/erasure call before selecting
the checked local verification target. It does not replace Rust source, alter
FnDef type translation or equate original and synthetic function types. Locals
holding function values, coercions, indirect calls, unresolved generic From,
other outputs/inputs and user From-like traits gain no foreign law.
