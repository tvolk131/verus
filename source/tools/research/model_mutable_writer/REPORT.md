# Changing the checked child payload

Normal compilation and full recursive kernel checking passed for all three
constants in trial005. The generic protocol threads arbitrary Rin to Rout
through the child while retaining the ancestor frame outside it. The byte child
law opens the existing unique loan, runs a supplied physical transformation,
and closes that same loan with the new initialized byte vector. The loan index
and original future remain the same. `child-results.json` records exact hashes
and the inherited FE/Eq_rect_eq assumption inventory.

The physical transformation is an explicit conditional WP premise. Opening its
payload consumes one explicit credit; the callback must account for its own
writes. It receives and returns genuine physical interval ownership, not pointer
metadata. Rin/Rout stay arbitrary so shared key resources need not become an
exclusive key vector.

This does not yet compose initialization, the mutating child, original-parent
recovery and actual final-memory observation into one public writer theorem.
That composition and a shared-key interface remain work in progress. Trials003
and004 were proof-development failures, not semantic negatives. The passing
one-constant protocol checkpoint remains separately recorded.

Actual Rust entry, provenance, ancestor loans, native operations/retags/phases
and C/F import remain unproved. Native correspondences are zero, full original
HMAC remains 1/1 and publication/goal completion remain false. Production,
original executable bodies and their domains are unchanged.
